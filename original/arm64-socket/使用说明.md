# 手机明文采集 → 电脑 Python 接收端

电脑端只用 Python 标准库 TCP，不启动 Frida CLI、Frida server、Python Frida API，也不自动打开游戏或注入。手机脚本仍需要你自己的 Frida JS 注入环境；换传输方式不保证解决注入/Hook 闪退。

## 使用

1. 电脑运行 `python receiver.py --serve`。监听地址仅 `127.0.0.1:28469`，无需开放局域网防火墙。也可运行 `start-receiver.ps1` 在后台启动。
2. 手机 USB ADB 连接正常时运行：

也可直接运行同目录 `setup-usb.ps1`；它只建立转发，不启动游戏、不注入。

```powershell
D:\Android-DevTools\sdk\platform-tools\adb.exe -s 10AF182G2600122 reverse tcp:28469 tcp:28469
```

3. 自行加载 `LaserCn69_SocketCapture.js`。手机连接 `127.0.0.1:28469`，ADB reverse 转给电脑接收器。脚本与 `receiver-config.json` 中的随机 token 必须配套，均留在本地。
4. 接收端看到 `PHONE CONNECTED` 只代表连接/认证成功。`lastPhase: capturing` 才表示采集点安装完成，`frames > 0` 才证明电脑接收到消息。
5. 如需登录明文，在登录握手发生前加载。已进入大厅再加载不会补抓之前的 10101。

电脑输出为本目录 `captures/lasercn-plain-时间戳-PID-随机值/`：JSONL、按方向和 ID 分类的 BIN、`summary.json`。BIN 中每条记录为大端 ID(u16)、长度(u24)、版本(u16)、明文消息体。手机不保存采集文件；网络连接前先完成认证，接收端不会保存认证 token。

接收端在 BIN 和 JSONL 都成功写入并 flush 后返回 ACK；脚本的 `frames` 为已入队，`sentFrames` 为已写入 TCP，`receiverFlushedFrames` 为接收端确认写入的帧数。flush 不是抵抗断电的持久性保证。没有包数上限，单条 4 MiB、队列 24 MiB；队列满或连接失败会停止 Hook，不自动重连或悄悄丢包。电脑须保持运行。

检查和停止：

```powershell
python receiver.py --status
python receiver.py --stop
```

建议先在手机 JS 控制台调用 `LaserCnCapture.stop()`，完成发送后再关闭接收端。强制杀进程可能丢失尚未发送的尾部。状态文件 `receiver-state.json` 只有元数据；JSONL/BIN 会包含登录凭据和聊天正文，不要公开上传。

## 如果仍闪退

本版本保留已核实的消息编解码 Hook，关闭了额外 UI 回调监听。它在每个 Hook 安装前向电脑发送 `before-hook` 诊断记录；原生崩溃未必能被 JS 捕获，最后一个事件只是定位线索，不是原因证明。

可将脚本顶部 `enableHooks: true` 改成 `false`，仅测试连接/心跳，不安装任何 Interceptor；这不会绕过或隐藏注入。本次没有自动做手机实验。

适配范围：国服 Android 69.114.1，ARM64，libg.so SHA256 `7b643e1c97a9a4a2778b46d0a2e0c3dfd3598f84e36f68f94abfa3dc6bce3aff`。脚本验证函数字节及虚表，不重新计算整个库哈希。真实手机 Socket/Hook 尚未验证；离线模拟测试不能证明不会崩溃。
