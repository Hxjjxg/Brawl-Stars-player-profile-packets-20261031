# PC 本机 10809 代理补测

时间：2026-11-01 17:39–17:44（北京时间）。按用户指定测试 `127.0.0.1:10809`，没有使用手机网络、游戏进程或 Frida。

结果：**代理端口和普通 HTTPS 可用，但本次未能通过该代理完成游戏握手，更未进入 token 登录或玩家查询阶段。**

| 检查 | 实际结果 |
|---|---|
| 本地监听 | 127.0.0.1:10809，Xray，mixed 入站 |
| HTTP CONNECT + 实际 Python 客户端 | 隧道建立；发送 10100（76 字节包体）后 EOF；未收到任何游戏消息 |

现有代理配置包含 `geoip:cn` / `geosite:cn` 直连规则，因此单纯指定代理端口不等于每个游戏目标都经过代理节点。为排除这项因素，额外启动过一个只允许游戏目标的回环测试监听，复用当前已配置的 proxy 出站。该对照依然失败。测试后已结束这个临时进程、删除临时凭据配置，原配置文件逐字节未变。

可以确定的边界是：连接在游戏 Hello 阶段就被关闭。尚不能仅凭这些结果区分代理上游限制、出口到国服的路径问题或服务端对该来源连接的拒绝。也不能把代理 CONNECT 成功当作游戏握手成功。登录 token 根本没有发送，因此本次结果不能用于判断它是否仍有效。

证据文件：

- `verification.json`：实际客户端的失败阶段，以及 sent / received 元数据；只发送了 10100，received 为空。
- `network-probes.json`：三台服务器 IP 的 SOCKS5 CONNECT 状态和 EOF 结果。
- `force-upstream-control.json`：强制走节点对照及原配置未改动的确认。

SOCKS5 协商与 CONNECT 按 [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928) 核对。本次未修改查询编码或加密实现；此前手机纯网络转发下的独立 Python 查询证据仍单独保留。
